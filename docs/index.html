Syntropy Health Architecture

Standards: HL7 FHIR R4 • SMART App Launch Framework • USCDI v3

1. System Overview

Syntropy Health is an open-source, local-first clinical data operating system designed to give individuals sovereign ownership of their longitudinal health records. Under the ONC Cures Act Final Rule, patients have a federal right to access their electronic health information (EHI) without special effort.

Syntropy Health implements the SMART on FHIR Standalone Patient Launch profile with PKCE (Proof Key for Code Exchange) to interface directly with certified EHR platforms (Epic MyChart, Cerner Millennium, Kaiser Permanente) and public testing sandboxes.

2. Architectural Model

[Healthcare Provider (Epic/Kaiser)]
│ (OAuth 2.0 + TLS)
▼
[Zero-Knowledge Relay: health.syntropylabs.io/callback]
│ (Client-side browser bounce)
▼
[Local App: localhost:8000] <─── 100% of data, tokens, & FHIR caching stays here

All data transformations, FHIR bundle normalization, clinical trend visualizations, and token storage execute in the local Python/FastAPI environment on your machine.

3. Supported USCDI v3 FHIR Resources

Patient.Read
Demographics, identifier, name, birth date, gender.
Observation.Read (Vitals)
Blood pressure, heart rate, BMI, SpO2, respiratory rate.
Observation.Read (Labs)
Metabolic panels, CBC, lipid profiles, reference ranges.
MedicationRequest.Read
Active prescriptions, dosages, ordering prescriber.
Condition.Read
Problems list, clinical status, verification status, severity.

4. Quickstart (Self-Hosted)

# Setup virtual environment & run local engine
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
./run.sh

The local dashboard launches at http://localhost:8000. All clinical and biometric data is stored locally in your private database.
